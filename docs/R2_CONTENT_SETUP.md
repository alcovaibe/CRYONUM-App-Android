# Лекции, политика, сайт и подписанный контент

## Текущий блокер доверия

ProductionContentKeys.TRUSTED_X509_KEYS пуст. Проверка закрытая: неизвестный keyId — отказ,
unsigned fallback отсутствует. На 2026-09-07 обычный GET получил манифест revision=1,
keyId=content-2026-01 с 12 лекциями и политикой v4.0. Все 13 файлов скачались, размеры, %PDF-
и SHA-256 совпали с полученным манифестом (2945899 байт суммарно). **Подлинность этого
манифеста не установлена**: совпадение хешей с недоверенным документом не создаёт доверия.

Владелец должен передать по доверенному каналу только публичный EC P-256 ключ
SubjectPublicKeyInfo (DER/base64) и подтвердить его fingerprint. Добавить его в карту ключей,
затем проверить подпись существующего манифеста. Получить ключ с того же неподтверждённого
сервера и автоматически довериться ему нельзя. Если private key утерян, владелец организует
новую offline-пару, подписывает новый манифест и доставляет публичный ключ обновлением APK.
В этом аудите инфраструктура и ключи не менялись.

## Контракт сервера

Только HTTPS `download.cryonum.com`, без редиректов. Манифест:
`manifests/content-v1.signed.json`. Пути ASCII, whitelist и фиксированные stable ID:
`lectures/v1/lecture-01.pdf` … `lecture-12.pdf`, `privacy-policy/v4.0/privacy-policy.pdf`.
Произвольные URL/пути из сервера не используются как локальные имена файлов.

Envelope/payload: schemaVersion=1, алгоритм SHA256withECDSA, DER-подпись base64url над
исходными UTF-8 байтами payload. revision — положительный Long без дроби/переполнения.
Максимум envelope 256 КиБ, файл 100 МиБ, совокупный контент 512 МиБ. Подпись, схема,
категории, ID, версии, длина, SHA-256 и допустимые пути проверяются до загрузки PDF.
Изменение состава файлов при той же ревизии отвергается при наличии проверенного кэша.
Ревизия ниже принятой отвергается; после удаления данных приложения локальная защита от
rollback начинается заново. Подписанное время истечения/удалённый transparency log не реализованы.

PDF: Content-Type application/pdf, отсутствие Content-Encoding, точная длина, magic %PDF-,
проверка SHA-256 перед публикацией. Возобновление требует сильного quoted ETag, Range и
If-Range, корректного Content-Range. HTML/редирект/неправильная длина не принимаются как PDF.
Публикация из .part атомарная; правильный старый файл не заменяется непроверенными байтами.
Файлы находятся в files/cryonum_content и переживают очистку cache; очистка app data/удаление
приложения их удаляет. При конфликтной миграции icy_content исходная копия теперь сохраняется.

UI предпочитает проверенный cached manifest для offline-открытия. Новый download/Worker
проверяет удалённый манифест. Без первого доверенного манифеста offline-загрузка невозможна,
проверка не ослабляется. Mutex сериализует изменение набора; cancel закрывает активный HTTP Call,
restart ожидает завершение записи. Kill/reboot/disk-full и foreground notification lifecycle
остаются устройственными тестами, не подтверждёнными одним JVM-валидатором.

Конфигурации сайта `https://cryonum.com/data/privacy-policy.json` и
`https://cryonum.com/data/site.json` читаются по TLS. Политика должна согласовывать versionCode,
versionName, contentManifestRevision и objectPath с подписанной записью. Неподписанная конфигурация
сама не разрешает PDF: открытие и принятие версии проходят через verifiedLocalFile. Telegram
ограничен разрешённой формой URL; TLS не защищает от ошибочного назначения канала самим сайтом.
PolicyConfigService/RemoteLinksService остаются на blocking OkHttp с timeout: немедленная отмена
их чтения отдельно не доработана, в отличие от подписанного манифеста/PDF.

## Публикация контента владельцем (не выполнена)

1. Новые PDF положить в новые versioned keys, не перезаписывать immutable старые версии.
2. Проверить размеры/хеши и %PDF-, затем offline подписать манифест с увеличенной revision.
3. Опубликовать PDF первыми, манифест последним, затем конфигурацию политики сайта.
4. Ключи подписи хранить вне Git/CI/APK/R2. Приложению нужен только публичный ключ.
5. Для PDF использовать immutable cache; манифесту дать короткий TTL/revalidation.
   Не ставить browser challenge на Android API; не удалять Range/ETag/Content-Range.

`tools/build_signed_content_manifest.py --help` описывает все аргументы. Скрипт проверяет
12 исходных английских имён (точная карта в tools/migrate_r2_layout.py), версии, размеры,
пути и пишет подписанный envelope атомарно. Ограничения диапазонов приведены к Android.
Он использует предоставленный offline private key, не создаёт/не публикует его.

`tools/migrate_r2_layout.py` по умолчанию делает read-only preflight; `--apply` копирует
объекты через R2 и меняет metadata. Это изменение инфраструктуры, **не разрешённое в текущем
аудите**, поэтому скрипт не запускался против R2. Не вставлять credential values в чат/логи.
Четыре теста чистой карты миграции прошли, успешность реального CopyObject не заявляется.

CORS относится к браузерному PDF.js сайта, не к native OkHttp Android. Его origins должен
подтвердить владелец сайта; полный аудит сайта и изменение Cloudflare здесь не выполнялись.
Для проверки Android достаточно обычных GET/HEAD на утверждённых объектах. Вредоносные MIME,
Range, обрывы и некорректные подписи проверять только MockWebServer/локальным стендом.
